# システム概要

## 対象構成
アプリケーションのソースは `src/`、ビルド・昇格・監視定義は `scripts/`（`build.js`, `promote-release.js`, `watch.js`, `update-new-sizes.js`）、配布物は `dist/`（本番）および `dist/preview/`（プレビュー）とする。`ktm-new.html` はエディション選択の入口で、容量表記をビルド・昇格時に更新する。`spinoff_pj_fork/` の別アプリケーションは対象外とする。

## 実行構成
バックエンド、DB、HTTPルーティングを持たないブラウザ内アプリケーション。HTMLにCSS・JavaScript・原稿・添付ファイルを内包して保存する。起動時は原稿が空でも閲覧モードとなる。

| ソース | 責務 |
| --- | --- |
| src/ktm.html | ツールバー、添付一覧、Markdown/CSSタブ、プレビュー、目次、設定、取込ダイアログ |
| src/js/kantanMarkdown.js | DOMイベント、300ms待機後の描画、添付解決、保存/書出し/取込、目次、テーマ、幅調整、改ページ目安、起動時・設定表示時のバージョン取得とキャッシュ再取得 |
| src/js/modules/*.js | 責務別モジュール（preview-mermaid.js、attachment-manager.js、save-export.js、settings-ui.js、update-init.js）。ビルド時にkantanMarkdown.jsと結合してインライン化する |
| src/js/kantanEditor.js | Tab、選択行のインデント、オートインデント、閉じタグ補助、Undo/Redo |
| src/js/kantanDrawer.js・src/kantanDrawer.html | 添付画像の矩形・文字・消しゴム・トリミング編集 |
| src/js/github-alerts.js | 5種類のGitHub Alerts変換、連続アラートの分割 |
| src/js/qiita_marker.js | Qiita公式互換Note記法（:::note info|warn|alert）解析・HTML生成、自己完結型インラインSVGアイコン埋め込み、marked Lexer/Parser拡張プラグイン（二重登録防止・段落誤吸い込み防止対応） |
| src/js/marked.min.js | Markdown解析。sanitizeは既定false。kantanMarkdown.js側のRenderer設定でfull/dev時のMermaidフェンスをdiv.mermaidへ変換。qiita_marker.jsによりNote記法を解析 |

| src/kantanUpdate.js | 更新確認、既存データ退避、HTML・script再構成、選択データ復元 |

## 保持と通信の境界
- 原稿とCSSはtextarea、添付はfileList配下のscript[type="text/template"]に保持。原稿の自動バックアップはない。
- LocalStorageはcom.tatesuke.ktm.接頭辞の設定値のみ。読書き例外は捕捉して既定値に戻す。
- 内蔵機能はサーバー保存を要求しない。ただし外部画像・リンク・CSS URL、ヘルプ、新規作成、更新操作は通信し得る。通信や漏洩が原理的にないとは保証しない。
- 更新ボタンは `https://hiro-gj.github.io/KanTanMarkdown/dist/kantanUpdate.js` をscriptとして読み込む。起動URLのパスに `/dist/preview/` を含む場合は `dist/preview/kantanUpdate.js` を使用する。いずれも `?t=現在時刻` を付加する。
- 起動後100msのタイマーと設定表示時に `https://hiro-gj.github.io/KanTanMarkdown/src/kantanVersion.txt` を `cache: no-store` で取得し、表示・hidden値へ反映する。HTTP/HTTPS起動ではクエリ・フラグメントを除く元URLを `cache: reload` で再取得する。失敗は捕捉し、画面再読込やコード置換は行わない。
- 任意HTMLとカスタムCSSを許可し、プレビュー全体のサニタイズを有効化していない。信頼できない文書を安全に開ける保証はない。保存時の「<」エスケープはtextareaの構造保護であり、XSS対策とは別。

## ビルド・CI/CD仕様
Node.js（v24+）および `esbuild` を使用し、`package-lock.json` で依存関係を管理する。`scripts/build.js` は一時ディレクトリへの反復ファイルコピーを行わず、メモリ上で独自CSS・JSの変換・圧縮を1回実行して各エディションを組み立てる。

| コマンド / スクリプト | 機能・生成物 |
| --- | --- |
| npm run build (`scripts/build.js`) | 全エディション（`ktm-dev.html`, `ktm-lite.html`, `ktm-std.html`, `ktm-full.html`）と `kantanUpdate.js` を `dist/preview/` へ生成し、`ktm-new.html` のプレビュー容量表記を更新（`dist/` 直下の本番成果物と本番容量表記は維持） |
| npm run build:dev (`scripts/build.js --dev-only`) | 圧縮なし・全ライブラリ内包の開発用 `dist/preview/ktm-dev.html` を生成 |
| npm run watch (`scripts/watch.js`) | `src/` 配下の変更をデバウンス監視し、開発用HTMLを自動再生成 |
| npm run promote:release (`scripts/promote-release.js`) | 確認済みの `dist/preview/` 成果物一式を本番 `dist/` 直下へ昇格し、`ktm-new.html` の本番容量表記を更新 |
| scripts/update-new-sizes.js | `dist/` および `dist/preview/` の実ファイルサイズを取得し `ktm-new.html` の容量表記を同期 |

`kantanUpdate.js` 生成時は `JSON.stringify` と `</script` エスケープを適用する。KaTeXは本体に未導入（Mermaidはfull/devに内包）。

### GitHub Actionsおよびデプロイ構成
ワークフローでは `actions/checkout@v7`、`actions/setup-node@v7`（npmキャッシュ有効）、`actions/configure-pages@v6`、`actions/upload-pages-artifact@v5`、`actions/deploy-pages@v5` を指定する。

- **CI テスト (`.github/workflows/test.yml`)**:
  - トリガー: `master` / `main` への push、pull_request（`paths-ignore` により `README.md`, `.gear/**`, `dist/preview/**` 変更時は発火除外）、および手動実行（`workflow_dispatch`）。
  - 内容: リポジトリのチェックアウト、Node.js 24 セットアップ、`npm ci` による再現可能な依存導入、`npm run build` による生成物ビルド、`npm test`（`.tests/run-tests.js`）による全自動テストスイート実行、および検証済み成果物アーティファクト（`dist/preview/` の4版・更新JS・`build-manifest.json` のみ。本番 `dist/`・`ktm-new.html`・`src/kantanVersion.txt` は含めない）の保存。
- **GitHub Pages デプロイ (`.github/workflows/deploy-pages.yml`)**:
  - トリガー: GitHub Release 公開（`release: published`）、`master` ブランチへの push（`paths` フィルタにより `src/**`, `scripts/**`, `package.json`, `package-lock.json`, `ktm-new.html`, `.github/workflows/deploy-pages.yml` の更新時のみ発火）、および手動実行（`workflow_dispatch`。入力 `tag` で昇格・公開するリリースタグを指定でき、省略時は最新タグ）。
  - 特徴:
    - **検証コミットの固定**: 作業ツリーはリリース時はタグのコミット、`master` push 時は push されたコミットそのものへ1回だけ `git checkout --detach` し、`npm ci`（同コミットの `package-lock.json`）・ビルド・昇格・テストをすべてそのコミットで実行する。タグのコミットは `origin/master` の履歴に含まれることを必須とする。
    - **リリース公開時（`release: published` / `workflow_dispatch`）**: 対象コミットの成功済み `test.yml` が保存した検証済み成果物をリポジトリ外の専用ディレクトリへ取得し（作業ツリーのファイルは上書きしない）、同コミットから `dist/preview/` を再ビルドしたうえで、`scripts/promote-release.js --version <tag> --source-sha <commit> --require-manifest --artifact-dir <取得先> --cross-check-dir dist/preview --sync-root <master worktree>` により、埋め込み版番号・`build-manifest.json`・ソースコミットSHA・全5ファイルの SHA-256・再ビルド結果の一致を照合して無改変で `dist/` 直下へ昇格する。`origin/master` への同期は別の `git worktree` で行い、同期コミットは本番 `dist/` 5ファイルと `ktm-new.html` の本番容量表記のみを対象とする（`dist/preview/` と `src/kantanVersion.txt` は変更しない）。公開用 `_site/` はその worktree（最新プレビュー＋昇格済み本番成果物）から作成し、公開済みリリースタグの強制移動は行わない。
    - **`master` マージ時（`push`）**: `npm run build` により `dist/preview/` と `ktm-new.html` のプレビュー容量表記のみを更新し、本番公開中の `dist/` 直下および本番容量表記を維持した上で `_site/` 経由で GitHub Pages へ公開する。


## 既知の制約
setViewOnlyは警告とツールバーボタン無効化のみで認可機構ではない。Safari判定はUAにsafariがありchromeがない場合で、APIの能力判定ではない。exportHTMLは描画DOM・カスタムCSS・テーマ変数・表示中目次を抽出する。Blob画像のData URL化、添付ストアの移送、本体印刷CSSや改ページ表示用CSS・再計算処理の移送は行わない。非同期描画の完了待機も行わない。
